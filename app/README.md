# Aussie Trainer

PWA для индивидуальной дрессировки австралийской овчарки: 12-недельный курс, пошаговые тренировки на прогулке с учётом каждой попытки, адаптация сложности, аналитика, дневник поведения и отчёт для ChatGPT или Claude. Полностью на русском, работает без интернета, все данные хранятся на устройстве. По желанию собаку можно сделать общей и вести вдвоём на двух телефонах — через Supabase.

## Быстрый старт

Нужен Node.js 20+.

```bash
npm install          # зависимости
npm run dev          # сборка + автопересборка + сервер http://localhost:5173
npm run build        # production-сборка в dist/
npm run preview      # раздать dist/ на http://localhost:4173
npm test             # модульные тесты (node:test через tsx)
npm run typecheck    # проверка типов TypeScript
npx playwright install chromium   # один раз, для сценарных тестов
npm run test:e2e     # сборка + сценарии Playwright
npm run test:sync    # два телефона + заглушка Supabase (сборка в dist-e2e/)
npm run test:sql     # SQL общей собаки на локальном PostgreSQL 16 (initdb/pg_ctl)
```

Если Chrome уже установлен, можно не скачивать браузер: `CHROME_PATH=/путь/к/chrome npm run test:e2e`.

Иконки пересоздаются из `scripts/icon.svg`: `npm run icons` (нужен Python 3 с Pillow и `rsvg-convert` или `cairosvg`).

## Публикация (бесплатный HTTPS)

Рекомендуется **GitHub Pages**. Сборка плоская — все файлы в корне `dist/`, без подпапок, поэтому их можно загрузить даже с iPhone или iPad через браузер:

1. github.com → «+» → New repository, например `aussie-trainer`, видимость **Public**.
2. Add file → Upload files → выбрать **все файлы** из `dist/` (`index.html`, `sw.js`, `manifest.webmanifest`, пять PNG) → Commit changes.
3. Settings → Pages → Source: Deploy from a branch → `main`, `/ (root)` → Save.
4. Через 1–2 минуты сайт откроется по адресу `https://<имя>.github.io/aussie-trainer/`.

Подойдут и Netlify, и Cloudflare Pages: любой статический хостинг с HTTPS. Все пути относительные, маршруты на `#/…`, настройка сервера не нужна.

**Обновление:** загрузить поверх изменившиеся файлы (обычно `index.html` и `sw.js`). При следующем открытии приложение покажет «Доступна новая версия» → «Обновить». Данные в IndexedDB при этом не трогаются.

**В этом репозитории** (`dog-trener`) готовый сайт лежит в корне, а исходники — в `app/`. Команда `npm run publish:root` собирает и копирует файлы в корень.

## Общая собака (два телефона)

Без аккаунта приложение работает только на одном телефоне. Чтобы вести собаку вдвоём, используется проект Supabase, общий с приложением «Бережно» — тот же аккаунт подходит для обоих.

**Подготовка облака (один раз):** Supabase → SQL Editor → вставить `supabase/aussie_trainer.sql` → Run. Скрипт создаёт только объекты с префиксом `aussie_` и приватное хранилище фото `aussie-photos`, «Бережно» не трогает; повторный запуск безопасен. Адрес проекта и публичный ключ — в `app.config.json` (или переменные `SUPABASE_URL`, `SUPABASE_ANON_KEY` при сборке; секретный ключ сборка отклонит).

**Подключение:** первый участник — «Настройки» → «Общая собака» → войти → «Сделать собаку общей» → «Отправить приглашение». Второй — на первом экране «Присоединиться к общей собаке» → войти → код из 8 символов. Данные телефона второго участника заменяются данными общей собаки.

**Как устроено.** Телефон всегда работает со своей IndexedDB. Каждая запись в синхронизируемые хранилища в той же транзакции ставит отметку в очередь `outbox`; очередь отправляется через 1,2 с после изменения и при опросе каждые 10 с, пока приложение открыто (а также при возврате сети и открытии приложения). В облаке одна таблица `aussie_records (pack_id, store, id, data jsonb, deleted, updated_at, server_updated_at)`: побеждает более позднее изменение (метка времени телефона автора, монотонная и не меньше уже увиденных чужих меток), удаления — мягкие. Изменения других забираются по курсору серверного времени с однократным запасом 10 с. Попытки — отдельные записи с уникальными id, поэтому если двое отмечают одно упражнение одновременно, после обмена у обоих счётчики пересчитываются из всех попыток и совпадают. Фото уходят в хранилище `aussie-photos/<pack>/<photo>` и скачиваются при первом показе. Доступ ограничен RLS: читать и писать может только участник стаи. Тренировка подписывается именем того, кто её начал («Кто проводил» в итогах, плане, отчёте и CSV).

## Установка на iPhone

1. Открыть адрес сайта **в Safari**.
2. «Поделиться» → «На экран „Домой“» → «Добавить».
3. Запускать с иконки и только потом вводить данные: у установленного приложения своё хранилище, данные из вкладки Safari туда не переходят.
4. Перенос на новый телефон: «Настройки» → «Сохранить резервную копию» → файл в «Файлы» → на новом устройстве на первом экране «Восстановить из резервной копии». Если собака общая — достаточно войти в аккаунт и присоединиться по коду.

## Архитектура

```
src/
  main.tsx, App.tsx       вход, маршруты на hash (#/today), нижняя навигация
  content/                данные курса: 21 упражнение с уровнями, 12-недельная программа
  domain/                 чистая логика без DOM — покрыта модульными тестами
    types.ts              модель данных
    plan.ts               справочник упражнений, описание пунктов, оценка длительности
    schedule.ts           создание курса, статусы дней, пауза, перенос, смена старта
    adaptation.ts         правила 70/80%, две сессии в сопоставимой обстановке, стресс
    training.ts           наблюдения, пересчёт попыток, подсказки безопасности
    metrics.ts            выполнение плана, доля успеха, уровни, успех по обстановке
    report.ts             недельный отчёт и текст для ИИ, JSON
    exporters.ts          ICS (календарь) и CSV
    backup.ts             формат резервной копии, проверка, миграции формата
  db/
    idb.ts                IndexedDB: версии схемы, атомарные пакеты, очередь отправки, уведомления
    store.ts              состояние приложения в памяти, перезагрузка после записи
    repo.ts               операции: тренировка, попытки, уровни, дневник, фото, копии
  cloud/                  общая собака: клиент Supabase (вход, RPC, фото), правила слияния, синхронизация
  screens/                экраны
  ui/                     дизайн-система: кнопки, листы, графики, диалоги
  sw.js                   service worker: офлайн-кеш, обновление по кнопке
scripts/build.mjs         сборка: esbuild + Tailwind v4 → один index.html
tests/unit, tests/e2e     модульные тесты и сценарии Playwright
tests/sync, tests/mock    два телефона + заглушка Supabase
tests/sql                 проверка SQL на PostgreSQL (вместе с миграцией «Бережно»)
supabase/aussie_trainer.sql  таблицы, функции и правила доступа общей собаки
```

**Данные.** IndexedDB `aussie-trainer`, схема версии 2: `settings, meta, outbox, dogs, programs, days, sessions, trainings, results, attempts, levels, levelChanges, journal, photos, customExercises, reports`. Каждая попытка — отдельная запись `attempts`, счётчики результата пересчитываются из попыток. Встроенные упражнения живут в коде (обновляются с приложением), свои — в `customExercises`. При изменении схемы увеличивается `DB_VERSION` и добавляется шаг в `upgrade()`; у резервной копии своя версия формата и `migrateBackup()`.

**Четыре показателя не смешиваются:** выполнение плана (adherence), доля правильных попыток, текущий уровень навыка, успех по обстановке (дом / тихое место / умеренные / сильные отвлечения). Пропуски и «не было встреч» не считаются неудачами; при сильном возбуждении удачные попытки не засчитываются.

**Стек.** React 19 + TypeScript, Tailwind CSS v4, иконки Lucide (`react-icons/lu`). По ТЗ предпочтительны Vite, Dexie, Recharts, vite-plugin-pwa и Vitest; в среде сборки не было доступа к npm, поэтому использованы эквиваленты без внешних зависимостей: esbuild, свой слой IndexedDB с миграциями, свои SVG-графики, свой service worker, `node:test`. Пользовательские возможности те же; развёртывание проще — сайт из 8 файлов. Файл `typings/react.d.ts` — компактные типы React вместо `@types/react`; если поставить `@types/react`, его нужно удалить.

## Проверено

- `npm test` — 61 модульный тест: шаблон курса (84 дня, недели 1–2 по ТЗ, все три направления каждый день недель 3–12), расписание, пауза, перенос, смена старта, правила адаптации, метрики, отчёт, резервная копия, ICS, CSV, правила слияния облачных изменений, клиент Supabase (вход, обновление токена, ошибки).
- `npm run test:e2e` — 15 сценариев в Chromium с размером iPhone 13: первый запуск, профиль, завершение упражнения, прерывание и восстановление после перезагрузки, пропуск, день отдыха, перенос, смена даты старта, переход между неделями, адаптация сложности, отчёт для ИИ и копирование, экспорт → удаление → импорт, офлайн, обновление service worker без потери данных, отсутствие горизонтальной прокрутки на 320/390/820/1280 px, наблюдения с подсказкой безопасности, дневник.
- `npm run test:sync` — два телефона: муж создаёт общую собаку с фото и начинает тренировку, жена присоединяется по коду и видит всё, включая фото и «проводит Саша»; одновременные попытки в одном упражнении сходятся у обоих (5 удачных, 1 неудачная); завершённая тренировка, запись дневника без сети (уходит при возврате сети), правка и удаление записи; неверный код; чужой пользователь не может читать данные стаи.
- `npm run test:sql` — SQL на PostgreSQL 16 после миграции «Бережно»: повторный запуск, коды приглашений, вход по коду, правила доступа, «побеждает более позднее», курсор, выход из стаи.
- Обновление с версии 1: данные существующей базы сохраняются, добавляется очередь отправки.

## Известные ограничения

- Без общей собаки данные живут только в браузере устройства. iOS может удалить их при нехватке места или очистке данных Safari — регулярно сохраняйте резервную копию.
- Синхронизация идёт, пока приложение открыто (опрос раз в 10 с); закрытое приложение догоняет изменения при следующем открытии. Если двое одновременно правят одну и ту же запись (например, профиль), остаётся более поздняя правка; попытки в упражнениях складываются.
- Напоминания работают внутри приложения; фоновых push-уведомлений нет. Для надёжных напоминаний — выгрузка расписания в календарь (.ics). Web Push — будущая функция (нужны сервер и согласие).
- Сценарные тесты выполнялись в Chromium; поведение Safari (установка, системное меню «Поделиться», Dynamic Type) нужно проверить на iPhone.
- Седьмой день каждой недели курса — отдых; при старте не с понедельника отдых выпадает на другой день недели. Настройка «Дни занятий» влияет на напоминания и календарь, а не на раскладку курса.
- Интерфейс рассчитан на одну собаку (модель данных допускает несколько).
- Длительность занятий — оценка по числу повторов.
- Фото в дневнике: до 4 на запись, уменьшаются до 1280 px.
